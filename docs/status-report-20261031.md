这里的“4 次”是普通主动调度的每日触发上限，不是承诺每天会收到 4 条消息：闲置、时间窗口、静音和模型选择沉默都会影响结果，调度计数也不等于实际送达数；一次主动回复还可能分为多个气泡。

未回复追问另有规则：她最后一句像问句、主人尚未回复时，在 15–40 分钟窗口内有 50% 概率交给模型决定是否追问，模型仍可选择沉默。**这类追问不占普通 `maxPerDay`。** 每条最后机器人消息最多尝试一次，但如果追问本身又成了新问句，可能再进入下一次窗口。因此不能把它称作“所有主动合计每天最多 4 次”或“无论如何只追问一次”。目前总开关关闭，这些分支均不运行。

用户尚未确定日常频率。以后需要确定普通每日次数、时间间隔、活动窗口和是否允许未回复追问；若要求严格的全天发送总上限或连续未回复后必停，还需要补充计数与停止规则。

DSH 系统服务限制写入范围为 `/srv/qqai-dsh`，禁用额外能力、限制命名空间与系统目录访问。安全 profile 移除了 Shell、文件操作、后台 jobs、子 Agent、插件管理、Web 终端和宿主文件树。可信插件本身仍在进程内执行，不能将其称作完全隔离的插件沙箱。

**还可以开启或扩展哪些功能**

以下是可选范围，并未替用户开启。涉及外部账号写操作、增加费用、扩大系统权限或公开网络访问时，仍须先明确范围和取得相应确认。

| 功能 | 可以做什么 | 开启所需工作 |
| --- | --- | --- |
| 日常主动陪伴 | 按闲置、时间窗口和频率主动私聊 | 确定频率与追问偏好，配置现有原生模块；真实行为尚未验收 |
| 更细的心情判断 | 每轮对话后用模型判断心情变化 | 可启用 `mood.judge`；增加辅助模型调用，无需新增宿主权限 |
| 调整模型/思考档 | 改模型或按会话指定模型与 effort | 核对已安装 provider、模型能力和 thinking 策略；新增服务需要凭据与费用确认 |
| 语音聊天 | 发语音、听用户语音、可选变声 | 选择 TTS/ASR 服务、准备音频转换，并适配 QQ 发送；当前适配器拒绝语音段，Ubuntu 无 Windows TTS 回退 |
| AI 生图 | 根据聊天要求画图并发到 QQ | 单独接入生图服务/凭据；现有 DeepSeek 聊天 Key 不代表具备生图接口；需增加受控图片投递 |
| 头像表情模板 | 用指定头像或上传附件制作表情 | 为图片来源建立专门限制，修改当前禁用入口；无需也不应开放任意服务器文件 |
| 更多表情行为 | 自动配图、收藏主人发的表情、分类备注 | 接入 Aurabot 原生模块并处理媒体来源及与 Neko 的重复发送；当前未收集 |
| 群聊/其他私聊 | 在选定群中回复、摘要群消息 | 指定白名单并扩展只允许主人私聊的适配器，确定群与个人记忆边界 |
| QQ 自身资料 | 查询或修改昵称、签名、头像 | 只读查询可单独设计；修改资料需显式权限，网关动作和图片来源需核对 |
| 好友申请管理 | 处理收到的申请、管理允许对象 | 启用 contacts 与细粒度权限；上游没有主动添加陌生人为好友的实现 |
| 群管理 | 禁言、解禁、踢人、头衔、公告 | 机器人必须有对应群权限，另设主人授权与群范围；当前关闭 |
| QQ 空间日记/互动 | 发说说、评论、点赞 | 明确发布受众和账号写操作授权，验证网关支持；不能直接沿用当前默认 `all` 公开发布 |
| B 站内容 | 浏览、分享、视频抽帧、可选评论回复 | 浏览与写操作分开；评论需平台登录凭据，抽帧需 ffmpeg，QQ 截图发送需媒体适配 |
| 抖音内容 | 独立浏览器浏览、分享、评论、主人私信 | 用户扫码、配置浏览器/Xvfb、核对主人平台身份、逐项写权限；本机链路未验证 |
| 小黑盒内容 | 游戏社区浏览、搜索、点赞、评论或发帖 | 另提供平台凭据并确定读写范围，不继承 QQ 权限 |
| 唱歌/RVC 翻唱 | 生成歌声片段、变声 | 上游安装流程偏 Windows，不能在 Ubuntu 直接开；需服务迁移、模型/资源/许可评估 |
| purpose 主动引擎 | 根据记忆和候选话题选择主动内容 | 属于另一套实验性引擎，应替换而非同时运行原生 speakup；需重新接线和验证 |
| 桌宠 | 用户电脑上的动画与气泡客户端 | 需要本机客户端、素材及安全隧道，不能只开云服务器模块就出现在桌面 |
| 指定文件发送 | 把明确目录内的文件发送给主人 | 增加目录、类型、大小和容器可达性限制；现有文件工具及发送入口均关闭 |
| 专用提醒/任务 | 日程提醒或受限后台工作 | 当前 longTasks 的 jobs/schedule 被移除；需设计专用任务能力，不能仅打开 UI 或恢复宽权限 Shell |

其中语音、群聊、非 Neko 图片、生图、文件发送均受当前适配器限制，必须适配后才能真实工作；“插件源码里有”与“这台服务器已经具备”应分开判断。

**可开放的程序接口**

| 接口 | 现有能力 | 当前状态及边界 |
| --- | --- | --- |
| OneBot HTTP / WS | 网关动作与 QQ 事件 | 已开启并使用；不需要为了接入 QQ 再开放公网 |
| Aurabot HTTP Bridge | `info`、`send`、`think`、`call`、`events` | 当前关闭；可供自己的程序请求状态、通知和人格回复；应保持 loopback/SSH 隧道与 Bearer token |
| DSH 会话 Bridge 工具 | `aurabot_qq_send`、`aurabot_status`、`aurabot_call` | 当前关闭；开启会扩大其他 DSH 会话对 QQ 的调用能力，需要限制使用者 |
| 同进程插件服务 | `ctx.get('aurabot')`，send/think/call/use/on/hub | 属于可信插件内部接口，不是已公开的 HTTP API；新增插件须核对代码权限 |
| 自定义本地接管接口 | TTS、ASR、生图、歌曲转换脚本 | 四项均关闭；需要编写可信脚本接入自建服务，保留 systemd 权限边界 |

Bridge 不能直接作为“已可靠可用的通知接口”打开：锁定上游 `src/core/bridge.js` 的 send、以及 think 的转发分支没有检查 `hub.deliver()` 的投递结果，存在投递未成功仍返回成功的代码路径。当前它关闭，因此没有把这条路径交给外部程序；后续开放前，应补上与现有 `qq_send_message` 一致的回执判断。`call` 可以访问模块函数，`events` 可含消息正文，还需要限定范围与数据暴露。

搜索与 Fetch 已可用，不属于等待开启的新功能。部署保留 DSH 的默认选择：搜索由 DeepSeek 服务端搜索实现，Fetch 使用本地 HTTP 抓取；独立 `/v1/tools/search` 和 `/v1/tools/fetch` 是另外的可选路由，不应混写为已经切换。用户已确认继续启用相关 Search/Fetch 并承担已说明的官方费用，但没有授权自动充值、升级服务器或购买新的语音、生图服务。
