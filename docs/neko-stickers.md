## 生效目标与日常行为

已部署的使用范围是 **大肥鱼单人套组**。本轮核查目录有 **286 张现成 GIF**；大肥鱼和 GPT 娘双人套组不进入模型选择或发送范围。数量是本次资源目录快照，限制规则按套组实施，不是永久固定 286 个文件名。

生效配置为 `ext.qqai-compat.stickerUsage = "normal"`。闲聊、调侃、庆祝、安慰等适合的语境可以自然配图，明确索要表情时优先响应；模型也可以只回文字。`normal` 是提示策略，**不表示固定概率、不要求每轮发图，也不另开主动消息定时器**。普通主动聊天仍由既有 Aurabot 调度决定是否发起。

每个完整模型回复轮次最多 **2 张**，包括该轮工具提前发送的图，以及最后多个气泡中的图。限额由真实 session/turn 标识和发送侧状态共同执行，不依靠模型自觉计数。同一轮相同 GIF 内容只保留一次；已经预留的额度遇到失败或不确定投递不会退还，避免重试额外发图。

这是每轮限制，不是每日总数或全局每分钟限制。下一轮有自己的额度；跨轮不要重复同一表情主要靠模型结合上下文判断，当前没有跨轮“最近 N 张绝不重复”的硬规则。Nekowhale 搜索对相近分数做小幅随机扰动，也不等于发送历史去重。

本次保持用户人格原文、DeepSeek Flash / Thinking Off、多气泡、记忆、搜索和既有主动聊天参数。QQ 自带小黄脸仍关闭，Aurabot 原生另一套表情库仍为 `stickers.enabled=false`、`autoChance=0`、`collect=false`；它们不控制 Nekowhale。

## 选图与文字模板

现成表情不是只按文件名随机挑选。上游知识库为每张图提供情绪、场景标签、画面说明、使用情境及部分梗信息。模型先用 `sticker_search` 检索，再按返回的标注选择 `sticker_send`。当前搜索结果默认是名称、情绪、前五个标签等简表；完整画面/用途/梗说明可通过 `sticker_manage info` 查看，提醒的候选选择则直接提供完整标注。不会把286款全部说明常驻塞进每轮上下文。该工具返回 Markdown 图片行，由模型放进最终回复，随后通过 QQ 适配器发送真实 GIF；它本身不等于已经向 QQ 发图。

需要贴合当下的个性短句时，可以使用 `meme_render` 的五种纯文字模板：

| 模板 | 标识 | 最长文字 |
| --- | --- | --- |
| 大肥鱼想 | `think` | 20 字符 |
| 大肥鱼举牌 | `sign` | 40 字符 |
| 大肥鱼葱卷 | `scroll` | 60 字符 |
| 大肥鱼上联 | `couplet_top` | 12 字符 |
| 大肥鱼下联 | `couplet_bottom` | 12 字符 |

这里按 Unicode 码点计数，不是模型 Token。新适配层拒绝超长文字，避免上游静默截断后被误认为完整表达。上游词语过滤保留，过滤结果应如实处理。“大肥鱼抱”需要头像图片，不在这次开放范围；任意本地图片路径、头像 URL 和外部图片输入继续被拒绝。

发送时再次校验现成图属于当前允许的单人库；文字模板必须来自受控模板调用，并登记生成来源。最终只允许受控资源目录内、字节检查通过且不超过 10 MiB 的 GIF，沿用现有 SnowLuma / OneBot 图片路径，保留原始动画字节。没有扩大宿主文件、Shell、Docker Socket 或任意 URL 读取权限。

模板来源登记只存在于 DSH 进程内，兼容模块热重载时保留，**DSH 进程重启后失效**。这不会删除聊天或历史图片文件，但模型不能直接重用重启前的模板 URL 发送；需要重新调用模板生成并登记，再发送。现成 GIF 仍按当前允许库检查。

## 为什么原生 `promptMode` 仍为 `off`

当前 QQ preset 使用 `persona.complete=true`。安装版本的 DSH 在该模式下只保留完整 persona section，Nekowhale 原生 `hint/index` section 不会进入 QQ 最终 system 提示。因此，仅把插件页面的 `frequency` 改成 `normal/often`，不能证明 QQ 模型实际收到了相应提示。

本项目继续保持 Nekowhale `promptMode: off`，保留图片工具；把实际使用策略接入 Aurabot 的动态 `rules`，随完整人格一起进入真实 QQ 提示。控制来源是 **`ext.qqai-compat.stickerUsage`**，不是 Nekowhale 页面原生的频率下拉框。只保留这一条实际生效的策略来源，避免两套配置显示不同。

适配层支持 `rare / normal / often` 三种主动使用提示，目标值为 `normal`。`off` 停止主动使用提示和专用提醒配图；它不是卸载工具，主人明确索要表情的能力仍存在。硬性单人范围和每轮最多 2 张与提示档位分开执行。

profile 的目标限制为：

```yaml
- id: nekowhale-stickers
  config:
    packs: ["大肥鱼"]
    whitelist: ["pack:大肥鱼"]
    promptMode: off
    autoSync: lazy
    templates: true
```

以上是目标字段示意，**不能用它覆盖整个 profile**。实际部署只更新指定字段，保留其余配置。模型的 `sticker_manage` 自选状态不能越过配置白名单，发送侧也会再次检查套组和当前启用状态。

## 专用提醒

专用提醒使用与聊天相同的 `normal` 策略、单人套组和五种文字模板。到点时，辅助流程读取当前人格和策略，让同一个 Flash / Thinking Off 模型决定是否配图。流程只让模型输出受限的选择数据，没有外部工具权限，不执行提醒正文中的指令，不改写已经保存的提醒正文。

若选现成图，先让模型给出场景词，再从知识库候选中选择；可不配图，最多两张。配图辅助流程最多使用两次小型模型请求。每次提醒 occurrence 使用独立的 `reminder:任务:时间` 范围，与聊天整轮分别计数，不占普通主动聊天日额度。

配图准备有 **20 秒硬截止**。模型、素材或模板准备失败、超时，就放弃配图并继续原正文的投递路径；迟到结果不能追加发图或再次发送提醒。这里的 20 秒只限制配图准备，实际送达还需要最后一次 QQ 身份检查和网关响应，不能承诺到点后必在 20 秒内收到。

提醒仍保留原有持久化占位、真实回执核对和不确定投递不自动重试机制。既有提醒时间、重复规则及明确设定的夜间提醒行为不因本次表情功能改变。

## 网络等待、缓存与已完成测速

新增固定源码补丁为 Nekowhale 每次资源下载设置：

| 项目 | 限制 |
| --- | --- |
| 单次请求尝试，包含响应正文 | 12 秒 |
| 同一资源含重试、退避和正文的总预算 | 30 秒 |
| 下载后实际读取字节上限 | 32 MiB |
| 重试次数 | 最多 5 次；模板缓存读取沿用最多 3 次，仍受总预算约束 |
| 取消 | 请求、正文读取和重试等待都响应父取消信号；不能依赖只拿到响应头就算完成 |

32 MiB 是网络资源上限，兼容字体等模板素材；QQ 最终 GIF 仍使用更严格的 10 MiB 限制。成功响应先读完有界正文，再交给现有缓存代码，避免把未完成的下载当成完整缓存。ETag / 304、不可变素材缓存和已缓存文件在上游失败时的回退行为保留。

**模板渲染没有新增端到端硬截止。** 一次模板可能读取多份素材、字体并执行本地渲染，因此每个资源的 30 秒不能解读为整个模板 30 秒；上游 `meme_render.timeoutMs=60000` 也只是合作式超时声明。专用提醒另有上述 20 秒截止，不会为等待配图无限推迟正文。普通聊天仍须观察模板实际耗时和工具结果。

服务器对三个未缓存单人 GIF 的只读下载测速已完成，均返回 HTTP 200，并通过 SHA-1 前缀和 GIF 文件头核对：

| 样本编号 | 本次下载耗时 |
| --- | --- |
| `10N01` | 0.231 秒 |
| `10N09` | 0.457 秒 |
| `12N01` | 0.799 秒 |

目录中 286 个单人 GIF 总大小为 **358,022,980 字节**；测速时服务器可用空间为 **46,751,432,704 字节**。这是样本和当时空间读数，不是长期网络速度保证。仍保留 `autoSync=lazy`，没有因此下载全部资源。

五种文字模板已完成实际渲染和素材预热，全部生成 300×300 GIF：上联 0.703 秒/40 帧，下联 1.269 秒/40 帧，想 0.629 秒/20 帧，葱卷 1.336 秒/40 帧，举牌 0.547 秒/30 帧。该检查未调用真实模型、未发 QQ，也不单独证明最终聊天中的视觉效果。
