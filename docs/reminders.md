## 在 QQ 中使用

直接对大肥鱼说清提醒事项和时间，例如：

- “半小时后提醒我取快递。”
- “明天晚上九点提醒我整理相册。”
- “每天早上八点提醒我喝水。”
- “每周六晚上九点提醒我整理相册。”
- “看看还有哪些提醒。”
- “取消编号为……的提醒。”

所有时间按北京时间（`Asia/Shanghai`，UTC+08:00）理解。时间不明确时应先确认。创建成功的工具结果包含任务编号和具体时间；只有实际保存成功，她才能说“已设置”。普通聊天中的口头答应或长期记忆不等于定时任务。修改时间采用取消原任务后重新创建，避免误改其他提醒。

## 调度与发送

| 项目 | 行为 |
| --- | --- |
| 类型 | 一次性、每天固定时间、每周固定星期与时间 |
| 时区 | 北京时间，循环任务固定本地时刻 |
| 检查间隔 | 5 秒；服务和 QQ 在线时到期发送，网络和处理耗时可能带来延迟 |
| 活跃数量 | 最多 50 个主人提醒 |
| 正文 | 最多 300 字符，原样作为提醒文字，不交给配图模型改写，也不执行正文中的命令 |
| 到点消息 | 同一次 `sendSegments` 提交正文及可选的 0–2 个图片段；有实际 QQ 消息回执才记录成功 |
| 模型调用 | 主人设置或管理任务时沿用现有对话模型；开启配图策略时，到点最多额外进行两次小型 Flash / Thinking Off 选择请求，模型可以选择不配图 |
| 配图策略 | 与聊天共用 `often`；仅大肥鱼单人套组及五种文字模板，每次提醒 occurrence 使用独立额度，最多 2 张 |
| 配图等待 | 模型和配图准备共用 20 秒硬截止；失败、超时或不需要图时回退到原正文投递，不追加迟到图片 |
| 夜间 | 主人明确指定的夜间提醒照常执行，不受日常主动聊天的 08:00–23:00 窗口限制 |
| 主动额度 | 不占用或修改原生 `speakUp` 每日 30 次普通主动尝试计数和排期 |
| 未回复 | 不追加追问，不重复催促 |
| 门禁 | 总开关、试运行、主人静音、QQ 在线状态和实际机器人身份均须通过 |

关机、离线或暂停期间的任务保留在私有文件中。恢复后，逾期不超过 24 小时的任务至多补发一次，并标明原定时间；逾期超过 24 小时的一次性任务标记过期，循环任务跳过积压排到未来。每个调度检查至多实际发送一条，避免积压任务同时刷屏。

配图准备读取同一个有效人格与表情使用策略，依据提醒场景和知识库标注选择；它没有工具执行权限，不执行提醒内容里的操作。现成图来自当前允许库，文字模板限于想、举牌、葱卷、上联、下联。头像、外部链接和任意文件图片不开放。配图与原正文在同一次发送中提交，不先发正文再追加独立图片消息。

20 秒限制的是配图准备，不是 QQ 最终送达时限；之后仍须核对当前主人、实际机器人身份、在线和静音状态，并等待网关回执。若到点后等待期间关闭模块、改变主人或失去发送资格，不会为了完成配图而绕过门禁。配图策略关闭或兼容模块不可用时，沿用纯文字提醒。

正常交互中，只有当前主人真实私聊请求中的短期随机授权令牌才能创建或取消任务；文章、小黑盒主动分享、系统主动回合和其他会话不能自行安排提醒。令牌绑定当前请求、主人与会话，最长有效 10 分钟；同一请求内相同创建操作重复执行会复用结果。工具不接受可选发送目标，始终发送给配置中的主人。

适配同时处理 DSH 提示钩子带 `session-` 前缀和工具注册不带前缀的会话标识，归一化后才匹配请求权限；执行时仍核对 Hub 中的真实主人私聊映射，不能仅凭字符串前缀取得权限。

## 回执、重启与不确定状态

发送前先原子保存“发送中”记录，再请求 QQ。收到有效 `message_id` 后才记为发送成功。若发生网络超时、没有回执，或进程在发送与记录之间中断，任务标记为“结果不确定”，自动调度不会重发该次提醒；循环任务也暂停，等待主人查询、核对后取消或重建。

这一策略减少重复提醒，但不能把跨网络发送称为严格“恰好一次”。存在 QQ 已收到、回执未保存的情况，也存在发送没有成功的情况；必须诚实保留不确定状态。损坏的状态文件或持久化写入失败会停止该模块，不能以空文件覆盖后继续运行。

首次安装工具 `deployment/install-reminders.py` 默认只安装关闭的模块；`--enable` 同时启用 `modules.qqai-reminders.enabled` 与 `ext.qqai-reminders.enabled`。安装前要求本模块关闭。安装清单包含全部三个 `.mjs` 文件，先写依赖，再写入口，避免遗漏配图 helper 导致模块加载失败。所有其他配置（包括人格、模型、记忆、搜索、小黑盒 Cookie 和主动聊天设置）必须在保存前后完全一致。安装器本身不请求模型或发送测试消息；启用调度后，已有到期任务按正常提醒规则执行，允许配图时也可能调用模型。

每次安装在指定 root 私有维护目录下创建独立 `reminders-*` 子目录，保存安装前配置、Aurabot 顶层 JSON 状态（包含记忆、会话映射、主动排期）、已有小黑盒/提醒状态及将被替换的提醒代码。读取前后核对文件稳定性，把备份重建到独立目录并逐字节、SHA-256 验证。备份与验证副本均为 root 私有，清单明确原始文件权限和缺失文件。

## 回滚与恢复

回滚先通过受保护的管理连接关闭 `ext.qqai-reminders.enabled` 和 `modules.qqai-reminders.enabled`。保留 `reminders.json` 及维护记录；需要退回代码时仅恢复该模块之前备份的文件与所属权限，然后重新加载模块。初次安装没有旧代码时，保持关闭即可，不必删除任务数据。

如果只需撤回本轮 Nekowhale 配图更新，按本轮维护记录恢复受影响代码及 `stickerUsage`、Nekowhale `packs/whitelist` 目标字段；不要因此清空或替换提醒任务。整套补丁恢复完成并通过 hash 检查后再启动 DSH，不重启 QQ 网关。

不要直接恢复整份旧 `config.json`，否则会覆盖随后变化的 Cookie 或其他设置；不要把旧 `speakup.json`、记忆或会话映射覆盖到正在运行的系统。恢复提醒状态前先停止该模块，验证备份哈希与 JSON，并核对已发出的提醒；将旧备份覆盖到当前任务文件可能重新引入已经发送的任务，必须先比对回执，不能盲目重放。

完整系统备份仍按项目既有备份流程执行；其可能停止网关，因此不能把该流程当作日常模块更新步骤。QQ 无人值守重启登录尚未通过，这项提醒接入不改变该结论。
