## 准备登录凭据

1. 在电脑 Edge 或 Chrome 打开 <https://www.xiaoheihe.cn/>，自行完成正常登录和必要验证。
2. 打开 F12 开发者工具的“网络 / Network”，刷新页面。
3. 选择发往 `api.xiaoheihe.cn` 的请求，在“标头 / Headers → 请求标头 / Request Headers”找到 `Cookie`。
4. 复制 Cookie 的完整值，保存到本地文本文件，例如 `C:\Users\Owner\Downloads\QQAI_HEYBOX_COOKIE.txt`。只提供文件路径，不发送 Cookie 正文或截图。

读取所需 Cookie 中必须有有效 `pkey`；完整登录请求还可能包含 `heybox_id` 等字段。不要复制响应中的 `Set-Cookie`，也不要在浏览器控制台执行来源不明的脚本。用户只授权阅读，不需要额外收集写操作令牌。[锁定版本上游说明](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq/blob/e9026a99d9db58974363c416eaa9e555499737fa/README.md#刷小黑盒)

Cookie 是登录凭据。运行侧通过项目私有 `heybox.cookie` 字段提供，不能写入模块源码、Git、日志、命令行参数或公开证据；不读取其他程序的 `~/.heybox-ai/credentials.json`。原始文件仅经严格主机指纹验证的 SSH 传入受保护的运行目录。

## 当前行为

- 独立用户模块 `qqai-heybox-reader` 复用锁定上游的网页请求签名，固定域名和只读接口；禁止重定向、写请求及任意 URL。
- 默认每 4 小时读取一轮、每轮最多 3 篇未读文章、北京时间 08:00–23:00 内运行，每日最多 6 轮。QQ 离线、主人静音、总开关关闭或试运行时不读取、不向主动回合添加文章。
- 文章正文是外部资料，不能作为指令。只把实际读取的文章提供给下一次原生 `speakUp` 主人私聊回合，由当前模型决定是否值得分享，至多选择一篇并带来源链接；没有合适内容可以不分享。
- 不增加第二个发信定时器，不手工触发主动消息，不修改原生 `speakup.json`。现有每日 20 次上限、30–60 分钟间隔、40 分钟闲置、08:00–23:00 和关闭追问继续生效。
- 原生 `heybox` 模块及其 `autoBrowse` 保持关闭，所有 `profilePerms.heybox*` 保持 `off`。这个适配不开放小黑盒写能力，也不修改人格、模型、搜索、记忆或媒体权限。
- 阅读、已提供给模型的文章与确认发出的分享分别记录。提供素材不等于模型选择分享；模型生成回复不等于 QQ 成功收到。已提供的文章不自动重试，以免重启后重复打扰。
- 去重集合各保留最近 1,000 个文章 ID；待用正文最多 3 篇、每篇最多 6,000 字符，48 小时后过期。读取时间不等于文章发布时间，不把缓存内容说成刚发生的新闻。
- 遇到登录失效、验证码或限流时暂停该阅读功能；不绕过验证或频繁重试。

阅读模块直接调用只读 `get_login_info` 核对 QQ 身份，缓存仅适用于当前连接和机器人配置，最多 5 分钟；断连、配置变化、卸载时失效。实际运行发现 `hub.selfId` 要收到新消息才会填充，因此没有用它作为启动前置条件，也不把配置号码当作已经登录的证据。身份修复通过热加载应用，没有重启 DSH 或网关。

## 原生模块为什么没有直接启用

锁定 Aurabot 1.1.24 的 `src/heybox/site.js` 定时路径调用未定义的 `hasLogin()`；后台回合是 system 会话，但 `src/modules/heybox/index.js` 对该类会话不提供小黑盒工具；后台结果也不会自动发送到 QQ。因此不能把“开启自动浏览”当作当前需求的完整实现。[上游业务代码](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq/blob/e9026a99d9db58974363c416eaa9e555499737fa/src/heybox/site.js)

本项目只新增用户模块，不升级或改写原生包。网页接口是否仍可用需要本次 Cookie 下的真实读取验证，不能凭签名源码存在就宣布可用。

## 部署与验证顺序

部署工具为 `deployment/install-heybox-reader.py`，复用项目已有的私有备份、原子写入和本机认证方式。默认只安装并保持功能关闭；`--cookie-file` 只接受服务器上 root 所有、0600 的普通文件；`--enable` 需要在真实只读探测通过后使用。

部署前备份当前私有配置与已有模块；核对签名实现 SHA256、既有小黑盒总开关/权限关闭。保存时只修改新模块设置及指定 Cookie 字段，核对其他配置和权限未变，不重启 DSH/网关，不重置原生主动状态。

验收必须分别记录：真实账号状态检查、真实信息流及文章正文获取、真实 DeepSeek 对文章的选择与回复、原生排期触发、QQ 回执和接收端结果。22 项 Node 24 合成边界回归已通过，不能替代这些真实步骤。

本次独立真实 API 核查记录位于服务器 root 私有目录 `/var/lib/qqai-dsh/maintenance/20261031-heybox/`。账号原始结果、Cookie、文章与模型草稿均保持私有。部署前配置和模块备份分别位于该目录的 `heybox-3_yj7wu5/` 与 `identity-fix-e13r6bdo/`；原生主动计数和排期没有修改。

回滚先关闭 `ext.qqai-heybox-reader.enabled` 和该模块，再由管理员移走本模块代码；不要恢复整份旧配置覆盖正在变化的其他设置，不要清空聊天、记忆或原生主动计数。模块的独立状态和私有备份保留用于排查。

Cookie 失效或验证阻断后，重新在官网正常登录/完成验证，并通过新的本地文件更新本项目凭据；不要向聊天发送凭据。替换凭据或更新模块前先关闭本模块的阅读开关。新 Cookie 会解除该模块的认证阻断并重新安排读取，但保留当日读取次数及已读/已提供记录，原生主动计数不受影响。
